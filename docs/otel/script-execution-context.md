# Message-scoped JavaScript execution context

Transformer JavaScript executes on a separate worker. The engine transfers an opaque listener snapshot using the original message's `LifecycleDispatchToken` before submission. `JavaScriptUtil.execute(task, token)` covers source/destination filters and transformers, response transformers, JavaScript and JDBC senders, pre/postprocessors, and attachment handlers. Binary attachment normalization preserves the incoming token before replacing the raw-message object. The no-script processor shortcut remains before capture.

This transfer creates no lifecycle operation or queue handoff. Capture must retain only immutable content-free context, with no producer handles, mutable message/maps, SDK provider or acquired lease. Pending snapshots can be discarded without listener callbacks. Bundle cancellation removes telemetry authority only; its `call` helper still runs the application callable without context after cancellation or previous consumption. The submitted Future controls application cancellation. The bundle grants attachment once, only to the exact original still-active registration. Unregistering and registering the same listener object does not revive an old token. Ordinary callback failures remain isolated and counted; fatal failures unwind successful sibling scopes in reverse order.

Only the worker closes an attached scope. Submission rejection and caller cancellation discard pending snapshots; cancellation after worker claim cannot close a foreign thread's scope. A script that ignores cancellation may outlive the waiting caller and still restores its worker scope in its eventual lexical return. Task exceptions and fatal context cleanup preserve fatal precedence. This change does not make cancellation equivalent to worker exit.

The context-free `execute(task)` remains the entrypoint for source polling, authentication, batch splitting, deploy/undeploy, and post-dispatch JDBC source updates. A channel id or returned message alone does not authorize revival of an ended context. Nested message-scoped submissions can use the token-aware overload and a listener's active borrowed binding; the legacy overload does not inherit context automatically.

Validation: `:donkey:test --tests '*ExecutionContextBundleTest' --tests '*MessageLifecycleListenersTest'` and `:server:test --tests '*JavaScriptUtilTest'`. Plugin-side full-flags, scope restoration, compatibility ABI and actual deployed HTTP recipe require their own integration evidence before the combined feature is complete.
